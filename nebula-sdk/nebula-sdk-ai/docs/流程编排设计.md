# 配置化 AI 流程编排引擎设计（nebula-sdk-ai · flow）

> 包：`com.nebula.common.ai.flow` ｜ 生成日期：2026-06-26

## 1. 目标

把「代码硬编码的编排图」升级为「数据库/配置驱动的流程编排」：

- 一个**流程**对应一张编排图（DAG）；
- 每个**节点**的提示词以模板（`#{var}` 占位）存储，运行时用上下文变量渲染后调用模型；
- 节点的**模型调用参数全可配**（provider/model/baseUrl/apiKey/timeoutMs/temperature/maxTokens/topP/stop/options），可借「模型档案」复用；
- 节点间用**边 + SpEL 条件**描述顺序与分支；
- 全程「改配置不改代码」即可调整/新增流程。

SDK 保持**存储无关**：出引擎 + SPI 接口 + 内存实现 + 本 DDL 文档；数据库实现由业务侧对接。

## 2. 概念映射

| 业务概念 | SDK 抽象 | 编排内核 |
|---|---|---|
| 流程 | `FlowDefinition` | `OrchestrationGraph`（code=flowCode） |
| 节点 | `FlowNodeDefinition` | `OrchestrationNode`（函数式） |
| 边/分支 | `FlowEdgeDefinition` | `OrchestrationEdge`（含 SpEL 条件） |
| 模型档案 | `ModelProfile` | —（参数来源） |
| 运行上下文 | — | `OrchestrationContext`（黑板：节点间传值） |

## 3. 运行时架构

```
FlowEngine.run(flowCode, input, userId, convId)
  │
  ├─ FlowDefinitionRepository.findByCode  → FlowDefinition（DB 或内存）
  ├─ FlowGraphFactory.build               → OrchestrationGraph
  │     · 节点：按 nodeType 选 FlowNodeExecutor，包装为 ctx -> executor.execute(node, ctx)
  │     · 节点档案规范化：profileCode 为空 → 继承流程 defaultProfileCode
  │     · 边：ConditionCompiler.compile(conditionExpr) → Predicate
  │     · 交由 OrchestrationGraph.Builder 校验引用合法 + 无环
  ├─ new OrchestrationContext(userId, convId)，写入 input + 保留键 __flowCode
  └─ DagOrchestrator.run(graph, ctx)       → 拓扑序 + 条件可达性执行
```

### PromptNodeExecutor（PROMPT 节点核心）

1. 变量池 = `ctx.attributes()`（上游产物 + 初始输入），再按 `inputMapping` 改名/挑选；
2. `AiTemplateUtils.render` 渲染 `systemPrompt` / `promptTemplate`；
3. **模型参数优先级合并**：`节点覆盖(非空) > 节点档案 ModelProfile > 流程默认档案 > 全局 AiProperties`；`options` 逐键合并；
4. 组 `AiRequest`（agentCode=flowCode，conversationId/userId 来自 ctx），调用 `AiService.chat`；
5. 写回产物：`outputMode=TEXT` → `ctx.put(outputKey, content)`；`JSON` → 解析后逐键展开并保留原文；`outputKey` 缺省用 `nodeCode`。

> 节点 A 配 `outputKey=topics`，节点 B 模板写 `#{topics}` 即自动衔接——纯配置驱动。

## 4. 扩展点（SPI）

| 接口 | 作用 | 默认/内置实现 |
|---|---|---|
| `FlowNodeExecutor` | 按 `nodeType` 实现节点执行逻辑 | `PromptNodeExecutor`(PROMPT)；可新增 SCRIPT/HTTP/SUBFLOW |
| `FlowDefinitionRepository` | 加载流程定义 | `InMemoryFlowDefinitionRepository`（业务可换 DB） |
| `ModelProfileRepository` | 加载模型档案 | `InMemoryModelProfileRepository`（业务可换 DB） |

新增节点类型：实现 `FlowNodeExecutor` 注册为 Bean，引擎自动纳入，无需改动核心。

## 5. 自动装配

`FlowAutoConfiguration`（`@ConditionalOnBean(AiService.class)`，在 `AiAutoConfiguration`/`AiAgentAutoConfiguration` 之后）装配：
`ConditionCompiler`、`ModelProfileRepository`、`FlowDefinitionRepository`、`PromptNodeExecutor`、`FlowGraphFactory`、`FlowEngine`，仓储均 `@ConditionalOnMissingBean`，业务声明 DB 实现即自动覆盖。

## 6. 配套数据库 DDL（业务侧实现 Repository 用；SDK 不依赖 MyBatis）

```sql
CREATE TABLE ai_model_profile (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  profile_code VARCHAR(64) NOT NULL,
  name VARCHAR(128) NULL,
  provider VARCHAR(32) NULL,
  base_url VARCHAR(256) NULL,
  api_key VARCHAR(256) NULL,
  model VARCHAR(64) NULL,
  temperature DECIMAL(3,2) NULL,
  max_tokens INT NULL,
  top_p DECIMAL(3,2) NULL,
  timeout_ms INT NULL,
  options TEXT NULL COMMENT '扩展参数JSON,透传厂商私有参数',
  status TINYINT NOT NULL DEFAULT 1,
  create_time DATETIME NULL, update_time DATETIME NULL, deleted TINYINT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_profile_code (profile_code)
) COMMENT='AI模型档案(连接+默认参数,可复用)';

CREATE TABLE ai_flow (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  flow_code VARCHAR(64) NOT NULL,
  name VARCHAR(128) NOT NULL,
  description VARCHAR(512) NULL,
  status TINYINT NOT NULL DEFAULT 0 COMMENT '0草稿 1启用 2停用',
  version INT NOT NULL DEFAULT 1,
  default_profile_code VARCHAR(64) NULL,
  create_time DATETIME NULL, update_time DATETIME NULL, deleted TINYINT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_flow_code (flow_code)
) COMMENT='AI流程定义';

CREATE TABLE ai_flow_node (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  flow_code VARCHAR(64) NOT NULL,
  node_code VARCHAR(64) NOT NULL,
  name VARCHAR(128) NULL,
  node_type VARCHAR(32) NOT NULL DEFAULT 'PROMPT',
  system_prompt TEXT NULL COMMENT '系统提示词模板(#{var})',
  prompt_template TEXT NULL COMMENT '用户提示词模板(#{var})',
  profile_code VARCHAR(64) NULL COMMENT '节点引用模型档案,空则用流程默认',
  provider VARCHAR(32) NULL, model VARCHAR(64) NULL,
  base_url VARCHAR(256) NULL, api_key VARCHAR(256) NULL,
  temperature DECIMAL(3,2) NULL, max_tokens INT NULL, top_p DECIMAL(3,2) NULL,
  timeout_ms INT NULL, stop VARCHAR(256) NULL COMMENT 'JSON数组', options TEXT NULL COMMENT '扩展参数JSON',
  input_mapping VARCHAR(1024) NULL COMMENT 'JSON:模板变量名->ctx键',
  output_key VARCHAR(64) NULL, output_mode VARCHAR(16) NOT NULL DEFAULT 'TEXT',
  node_config TEXT NULL COMMENT '非PROMPT类型扩展配置JSON',
  remember_trace TINYINT NOT NULL DEFAULT 0, sort_no INT NOT NULL DEFAULT 0,
  create_time DATETIME NULL, update_time DATETIME NULL, deleted TINYINT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_flow_node (flow_code, node_code), KEY idx_flow (flow_code)
) COMMENT='AI流程节点(含提示词模板与模型参数覆盖)';

CREATE TABLE ai_flow_edge (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  flow_code VARCHAR(64) NOT NULL,
  from_node VARCHAR(64) NOT NULL, to_node VARCHAR(64) NOT NULL,
  condition_expr VARCHAR(512) NULL COMMENT 'SpEL,空=无条件直达',
  sort_no INT NOT NULL DEFAULT 0,
  create_time DATETIME NULL, update_time DATETIME NULL,
  KEY idx_flow (flow_code)
) COMMENT='AI流程边';
```

DTO ↔ 表字段一一对应；业务侧实现 `FlowDefinitionRepository`/`ModelProfileRepository` 按 flow_code/profile_code 组装 DTO 即可。

## 7. 编程式使用示例（内存仓储，无需数据库）

```java
// 1. 注册模型档案
InMemoryModelProfileRepository profiles = new InMemoryModelProfileRepository();
profiles.register(new ModelProfile().setProfileCode("default")
        .setModel("gpt-4o-mini").setTemperature(0.7));

// 2. 定义流程：classify -> (series | single)
FlowDefinition def = new FlowDefinition().setFlowCode("router").setDefaultProfileCode("default");
def.getNodes().add(new FlowNodeDefinition().setNodeCode("classify")
        .setPromptTemplate("判断意图：#{q}，只回 series 或 single").setOutputKey("intent").setSortNo(0));
def.getNodes().add(new FlowNodeDefinition().setNodeCode("series")
        .setPromptTemplate("围绕 #{q} 规划系列").setOutputKey("plan").setSortNo(1));
def.getNodes().add(new FlowNodeDefinition().setNodeCode("single")
        .setPromptTemplate("围绕 #{q} 写单篇").setOutputKey("article").setSortNo(2));
def.getEdges().add(new FlowEdgeDefinition().setFromNode("classify").setToNode("series")
        .setConditionExpr("getString('intent') == 'series'"));
def.getEdges().add(new FlowEdgeDefinition().setFromNode("classify").setToNode("single")
        .setConditionExpr("getString('intent') == 'single'"));

// 3. 运行（容器中通常直接注入 FlowEngine）
OrchestrationContext ctx = flowEngine.run("router", Map.of("q", "Spring 入门"), "u1", "c1");
String plan = ctx.getString("plan");
```

## 8. 边界与后续

- SCRIPT/HTTP/SUBFLOW 执行器留作 SPI 扩展点（字段 `node_type`/`node_config` 已预留）。
- 编排为单线程 `DagOrchestrator`；并行策略可实现 `Orchestrator` 接口替换。
- 后台 CRUD/可视化编辑器、流程运行轨迹落库由业务侧实现。
