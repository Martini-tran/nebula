多用户形态：每位作者独立账号、各写各的书，互不可见。登录方式为邮箱 + 密码。 与 scribe-home.html 及三份内页原型同令牌同组件。 表单遵循仓库既有的表单 UX 规范：标签在上、呼吸感间距、五态反馈、必填懒校验。

重要更正：登录注册不由 scribe 实现。 全仓已有统一账号体系——sys_user 表 + 网关 AuthGlobalFilter（Sa-Token） + 已在白名单的 /manager/auth/login|register|logout。 本页表单的视觉与交互可直接复用，但提交目标是 manager 而非 scribe； scribe 只读网关注入的 X-User-Id。详见 docs/写作Agent设计.md §6.5。

六、与后端的对接

前端已有 src/stores/auth.ts，但目前只是把 isLoggedIn 与 token 存进 localStorage 的本地桩，没有任何真实登录请求。

已存在、直接用：POST /manager/auth/login · POST /manager/auth/register · POST /manager/auth/logout · /manager/captcha/**（均已在网关白名单内）

scribe 侧才需要新建的：GET|PUT /scribe/account/pref（写作偏好）· POST /scribe/account/export（导出全部数据）· DELETE /scribe/account/data（删除本人全部写作数据，含 Milvus 侧）

鉴权链路：网关 AuthGlobalFilter（order = -100）校验 Sa-Token 后注入 X-User-Id，并会先剥掉外部传入的同名头防伪造。scribe 不解析 token， 只读这个头。但要注意——网关只证明「你是谁」，不证明「这本书是你的」： 资源归属校验仍是 scribe 自己的责任，每个接口都要比对 user_id。
