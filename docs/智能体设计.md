# Ganet 智能体架构设计（Draft v1）

## 一、设计理念

Ganet 并不是一个单纯的 Workflow 平台，也不是一个单纯的 Agent 框架。

它的核心理念是：

> **Workflow 是 Agent，Agent 也是 Workflow。**

Workflow 可以包含多个节点，其中 **Agent 节点**既可以是：

- LLM Agent（直接调用模型）
- Workflow Agent（调用另一个 Workflow）

因此整个系统天然支持递归调用。

例如：

```text
Workflow A
│
├── LLM
├── Tool
├── Agent（Workflow B）
│        │
│        ├── Tool
│        ├── LLM
│        └── Agent（Workflow C）
│
└── End
```

整个框架只有一种执行模型。

---

# 二、核心对象

整个 Ganet 建议划分为四个核心对象。

```
Agent Definition
        │
        ▼
Agent Instance
        │
        ▼
Execution Context
        │
        ▼
Agent Memory
```

---

## 1、Agent Definition（智能体定义）

Agent Definition 是静态定义。

例如：

```text
旅游规划Agent
```

里面保存：

- Workflow
- 节点配置
- Prompt
- 输入参数
- 输出参数
- Memory Import 配置
- Memory Export 配置

Definition 永远不可修改。

它类似于：

```java
class TravelAgent {}
```

---

## 2、Agent Instance（智能体实例）

每次执行都会产生一个新的 Instance。

例如：

```text
TravelAgent

↓

Instance-001
```

再次执行：

```text
TravelAgent

↓

Instance-002
```

Instance 生命周期：

```text
创建

↓

执行

↓

结束

↓

销毁
```

因此：

- 点击执行
- API 调用
- 定时任务

本质都是创建新的 Instance。

---

## 3、Execution Context（执行上下文）

Execution Context 是整个运行时真正的核心。

所有节点：

- Tool
- LLM
- Agent
- If
- Loop

都只操作 Execution Context。

建议包含：

```text
ExecutionContext
│
├── Inputs
├── Variables
├── Messages
├── Artifacts
├── Local Memory
├── Metadata
└── Outputs
```

说明：

### Inputs

开始节点输入。

例如：

```json
{
    "question":"帮我规划去日本旅游"
}
```

---

### Variables

流程变量。

例如：

```text
budget

city

hotel
```

---

### Messages

LLM Message。

例如：

```text
User

Assistant

Tool
```

---

### Artifacts

文件。

例如：

```text
pdf

image

excel
```

---

### Local Memory

本次执行产生的数据。

生命周期：

仅当前 Instance。

---

### Metadata

例如：

```text
TraceId

StartTime

TokenUsage

RetryCount
```

---

### Outputs

Workflow 输出。

---

## 4、Agent Memory（长期记忆）

每个 Agent 自己拥有一份长期 Memory。

例如：

```text
Travel Agent
```

拥有：

```text
Travel Memory
```

Coding Agent：

拥有：

```text
Coding Memory
```

Customer Agent：

拥有：

```text
Customer Memory
```

它们互不影响。

Agent Memory 生命周期：

```text
Agent 创建

↓

一直存在

↓

Agent 删除

↓

Memory 删除
```

---

# 三、执行流程

建议执行模型：

```text
创建 Instance

↓

Import Agent Memory

↓

创建 ExecutionContext

↓

Workflow Execute

↓

Export Memory

↓

结束
```

详细流程：

```text
Agent Definition

↓

Create Instance

↓

Import Memory

↓

ExecutionContext

↓

Workflow Execute

↓

ExecutionContext

↓

Export Memory

↓

Agent Memory
```

整个执行过程中：

所有节点：

只操作：

ExecutionContext。

绝不直接修改 Agent Memory。

---

# 四、Memory 生命周期

## Import（导入）

Workflow 开始：

读取：

```text
Agent Memory
```

导入：

```text
ExecutionContext
```

例如：

```text
Agent Memory

↓

userProfile

↓

ExecutionContext.userProfile
```

---

## Runtime（运行）

Workflow：

一直操作：

```text
ExecutionContext
```

例如：

```java
context.put("travelPlan", result);
```

而不是：

```java
agentMemory.put(...)
```

---

## Export（导出）

Workflow：

结束：

生成：

Memory Changes。

例如：

```json
{
    "summary":"用户喜欢东京",
    "preference":{
        "city":"东京"
    }
}
```

最后：

写回：

```text
Agent Memory
```

---

# 五、为什么不直接修改 Agent Memory？

因为：

一个 Agent：

可能同时运行多个 Instance。

例如：

```text
TravelAgent

↓

Instance-001

↓

Instance-002
```

如果：

两个 Instance：

同时：

```text
agentMemory.put(...)
```

容易产生：

- 覆盖
- 数据冲突
- 并发问题

因此：

建议：

所有修改：

最终统一 Export。

---

# 六、Workflow Agent

Workflow 中：

Agent 节点：

可以引用：

另一个 Workflow。

例如：

```text
Workflow A

↓

Agent

↓

Workflow B
```

Workflow B：

本质：

也是：

Agent。

因此：

Workflow 可以无限递归。

---

# 七、Workflow Agent 数据共享

建议：

默认：

不共享 Memory。

而是：

采用：

Input Mapping。

例如：

```text
Workflow A

city

budget

↓

Workflow B
```

Workflow B：

输入：

```text
city

budget
```

Workflow B：

结束：

输出：

```text
travelPlan
```

返回：

Workflow A。

而不是：

共享整个 Memory。

---

# 八、为什么采用 Agent Memory，而不是 Project Memory？

Project Memory：

```text
Project
│
├── Agent A
├── Agent B
└── Agent C
```

所有 Agent：

共享：

```text
Project Memory
```

问题：

- 数据污染
- 权限复杂
- Agent 耦合

因此：

采用：

```text
Project
│
├── Travel Agent
│      └── Memory
│
├── Coding Agent
│      └── Memory
│
└── Customer Agent
       └── Memory
```

每个 Agent：

拥有自己的长期记忆。

互不影响。

```text
          │           │           │

          │
          ▼

          ▼

```

# 十、架构定位

Ganet 不属于：

- Message Driven
- Memory Driven

而是：

> **Workflow Orchestrated + Execution Context Driven + Agent Memory Backed**

即：

- Workflow 负责流程编排。
- Execution Context 负责运行时状态。
- Agent Memory 提供长期记忆。
- Agent Definition 定义智能体。
- Agent Instance 负责一次执行。
