登录与访问

个人空间的每个页面都需要登录——书签按账号隔离，未登录访问任意地址都会被路由守卫带到 /login?redirect=原地址。 账号不由 space 自建，复用 manager 的 sys_user 体系：POST /manager/auth/login（用户名 + 密码 + 一次性验证码令牌）， 验证码为 /manager/captcha/get|check 的滑块拼图，均在网关白名单内。六节：登录页、滑块验证、错误态、登录失效回跳、无空间权限、首次进入。

一、登录页

左侧用产品自己的书签卡片做预览，一眼说明这是什么；右侧只有用户名、密码两个输入框。 验证码不常驻页面——点「登录」且表单填好后才弹出，拼图通过即自动提交，不用再点第二次。 底部说明账号与 Nebula 其他应用通用，避免用户以为要单独注册。

三、错误态

字段级：懒校验，点过一次「登录」后才对空字段标红，文案就地显示在输入框下。 表单级：后端返回的文案放在表单顶部红条，不区分「用户名不存在」与「密码错误」，避免泄露账号是否存在； 若后续加入失败锁定，应给出剩余次数或等待时间，而不是只说「失败」（右图为该提议的样子）。验证码图片加载失败时整块变成「点此重试」。

四、登录失效回跳

Token 过期（30 天）或在别处退出后，任意请求返回 401 → request.ts 清本地登录态并跳 /login?redirect=/?folder=12。登录页顶部用蓝色信息条（不是红色错误）说明原因，并写出登录后会回到哪里； 用户名预填上次的账号。redirect 只接受站内路径，防止被拿来跳外站。

五、已登录但没有空间权限（403）

空间接口都挂在 /space/admin/**，逐个校验 space:bookmark:*、space:folder:*、space:tag:* 等权限。 统一账号能登录，不代表开通了空间——这时不能把用户踢回登录页（会死循环），而是停在一个说明页： 你是谁、缺什么、找谁开，并允许换账号。首个请求返回 403 时进入此页。
