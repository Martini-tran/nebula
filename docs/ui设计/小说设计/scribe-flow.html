流程编排 · Scribe 样式

ui/nebula-ui/apps/web-ele/src/views/ai-flow（Element Plus + X6，74 文件 / 约 1.3 万行） 在 Scribe「纸与墨」设计语言下的样子。结构、节点类型、配置项均对齐现有实现，本页只改视觉层。

定位已确定：画布留在管理端，不迁进 scribe。 普通作者不需要编排画布——他们要的是「点润色」，不是「拖一个 LLM 节点连到 IF 节点」。 manager 已有完整一套（views/ai-flow + 路由 + 编辑器布局守卫），迁移是纯负债； 也避免把 Element Plus + X6（500KB+）+ CodeLayout 引入零组件库的 scribe。
所以本页现在的用途是： manager 端 ai-flow 若要做视觉改版时的参考稿。 其中「AntD 五色 → 语义四档」的配色方案独立成立——那套高饱和色在任何界面里都偏吵。 是否改版是独立决策，与 scribe 无关。详见 docs/写作Agent设计.md §7.4。
移植的核心问题是配色。现有实现用的是 AntD 的 blue/green/orange/purple/red（见 editor/constants.ts 的 THEME_COLORS），五个高饱和色摆在一起，跟 Scribe 的米白纸面完全冲突。 这里改成按语义分四档并全部落进纸墨体系： 流程=中性墨、模型=品牌赭石、工具=靛青、分支=暖橙偏赭； 只保留紫色给子 Agent——它语义上确实需要跟其他四类拉开距离。

四、若要在 manager 端落地，改哪几处

结构完全不动：工具栏 / 节点面板 / 画布 / 右侧配置三栏、节点类型清单、 配置项字段、事件流语义，全部对齐 views/ai-flow 现有实现。

成本低、收益直接的两处（可单独做，不牵动组件库）： ① editor/constants.ts 的 THEME_COLORS：AntD 五色 → 本页语义四档 + 紫； ② 同文件 RUN_STATE_COLOR：Element Plus 四色 → 赭石 / 靛青 / 绛红 / 降透明。 这两处都是改常量表，不动组件，是性价比最高的部分。

成本高的一处：Element Plus 组件（el-input/el-select/el-dialog…） 若要完全统一到纸墨体系，需覆盖其 CSS 变量或换成手写组件——涉及几十个弹窗与表单， 这是大头，建议先不做，或只覆盖 Element Plus 的主题变量做浅层统一。

建议的取舍：先只做上面两处常量改动，画布立刻不吵了； 组件层等有余力再说。管理端是自用工具，视觉一致性的优先级本就低于作者端。
