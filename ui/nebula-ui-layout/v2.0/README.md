# Nebula Admin v2.0 — 混合导航（顶部大类 + 侧边子菜单）

在 v1.0 基础上改导航结构：**一级大类放顶栏，点击后侧栏展示该类子菜单**。
视觉令牌（主色/圆角/表格）与 v1.0 完全一致，**只有导航结构不同**，方便直接对比。

双击 `index.html` 即可查看，无需构建。

## 文件

| 文件 | 说明 |
|---|---|
| `tokens.css` | 与 v1.0 **完全相同**，未改动 |
| `layout.css` | 与 v1.0 **完全相同**，未改动 |
| `layout-v2.css` | **v2 增量**：顶栏一级导航 + 侧栏改浅色面板 |
| `index.html` | 列表页，顶部大类可点击切换 |
| `form.html` | 表单 + 弹窗 + 组件规范总览 |

## 与 v1.0 的结构差异

```
v1.0                              v2.0
┌────────┬──────────────┐         ┌──────────────────────────┐
│ 深色   │  顶栏        │         │ 深色顶栏：一级大类导航    │
│ 侧栏   ├──────────────┤         ├────────┬─────────────────┤
│        │              │         │ 浅色   │                 │
│ 全部   │   内容区     │         │ 侧栏   │    内容区       │
│ 菜单   │              │         │ 当前类 │                 │
│ 平铺   │              │         │ 子菜单 │                 │
└────────┴──────────────┘         └────────┴─────────────────┘
```

**明暗关系对调**：v1 是「深侧栏 + 浅顶栏」，v2 是「深顶栏 + 浅侧栏」。
因为 v2 的导航重心在顶部，深色跟着导航走；两处都深会抢视觉重心。

## 顶部大类划分

按业务域归并了原来的 13 个路由模块：

| 顶部大类 | 侧栏子菜单（含二级分组） |
|---|---|
| 工作台 | 分析页、工作台 |
| 博客 | **内容**：文章/随笔/标签/分类/系列　**任务**：导入任务 |
| AI 能力 | **智能体**：定义/实例/回放/迭代链　**编排**：流程列表/AI对话　**模型资产**：知识库/MCP/模型档案/提示词/AI工具 |
| AI中转 | 服务商/套餐/套餐类型/AI模型/支付方式/推荐测评/充值记录 |
| 个人空间 | 书签/目录/标签/导入/导出任务 |
| 系统 | 用户/文件/菜单管理 |

> 这里把原本分散的 `ai-knowledge` / `ai-mcp-server` / `ai-model-profile` / `ai-prompt` / `ai-tool`
> 五个模块（它们在现有路由里 order 都是 305、title 都叫「AI模型」，实际是被拆散的同一组）
> 收进「AI 能力 → 模型资产」分组。这是 v2 结构带来的直接收益。

## 顶栏规格

一级导航为**图标在上、文字在下**的两行结构：

| 项 | 值 | 变量 |
|---|---|---|
| 顶栏总高 | 68px | `--topnav-height` |
| 导航项高 | 54px | — |
| 导航项最小宽 | 76px | `--topnav-item-width` |
| 图标 | 21px，描边 1.6 | `.topnav__icon` |
| 文字 | 13px | `--font-sm` |

两个配套处理：

- **徽标改绝对定位**到图标右上角。两行结构下徽标不能再占行内位置，
  否则会把文字挤偏。徽标带 1.5px 描边（颜色跟随底色），选中态自动
  换成主色描边，避免深色描边压在主色块上显脏。
- **窄屏（≤1280px）不隐藏文字**，只收窄间距（item 宽 64px、字号降到 12px）
  并隐藏 logo 文字。两行结构里文字是主要辨识依据，藏掉就失去了这版的意义。
  实测 1200px 视口下无横向溢出。

## 交互

- 点顶部大类 → 侧栏整体换成该类子菜单，并**自动选中第一个子项**，面包屑/页签同步更新
- 点侧栏子项 → 切换当前页
- 点左下「收起菜单」→ 侧栏折叠为 60px 图标栏

菜单数据在 `index.html` 底部的 `MENU` 常量里，结构与后端 `/system/menu/all`
下发格式一致（一级 = 大类，`children` = 子菜单，`group` 字段做二级分组）。

## 两版怎么选

**v2.0 更适合本项目**，因为：

- 现有 13 个路由模块、约 45 个页面，v1 全平铺在侧栏需要大量滚动
- 「AI 能力」下有 11 个子页面，v1 里必须折叠成多层手风琴，层级深
- 业务域切换频率低、域内页面切换频率高 —— 正好匹配「顶部切域 + 侧边切页」

**v1.0 更适合**：菜单总量少（< 20 页）、或用户需要频繁跨域跳转的场景。

代价：顶栏大类数量受宽度限制（当前 6 个，1180px 以下自动只留图标）。
若以后大类超过 8 个，需要加「更多」下拉。

## 落地注意

v2 的路由 `meta` 需要能区分「一级大类」和「子菜单」。现有路由已经是
两层结构（父分组路由 + children），**不需要改数据结构**，只需布局组件
改为读第一层渲染顶栏、读 children 渲染侧栏。

其余落地事项同 v1.0 README（改 `preferences.ts` 记得升 `VITE_APP_NAMESPACE`）。
