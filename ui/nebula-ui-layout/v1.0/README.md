# Nebula Admin — Layout 设计稿

纯静态 HTML 设计稿，用于**定稿视觉规范**，定稿后再落地到 `apps/web-ele`。
不含任何构建，双击 `index.html` 直接看。

## 配色对比（右下角切换器）

`index.html` 右下角可切换五套主色方案：
**青绿 / 原配色 / 靛蓝 / 暖砂 / 珊瑚**。

后四版分别由 `tokens-origin.css` / `tokens-indigo.css` / `tokens-sand.css` /
`tokens-coral.css` 提供，**只覆盖颜色，不改任何尺寸/圆角/密度**，
所以五版布局完全一致，差异纯粹在色彩上。

> **只做浅色主题。** 侧栏统一为浅色，不再维护深色变体——
> 一套设计出两套颜色意味着每加一个方案都要配一套对应主题色，
> 维护成本翻倍而收益很小。原先的「深色/浅色侧栏」切换器已移除。

| | 青绿版 | 原配色版 | 靛蓝版 | 暖砂版 | 珊瑚版 |
|---|---|---|---|---|---|
| 主色 | `#0D9488` | `#006BE6`（框架默认）| `#4F46E5` | `#15803D` | `#0F766E` 深青 |
| hover | `#0F766E` | `#0058BD` | `#4338CA` | `#166534` | `#115E59` |
| success | `#16A34A` 草绿 | `#57D188` 浅绿 | `#047857` | `#3F6212` 橄榄 | `#15803D` |
| warning | `#D97706` | `#EFBD48` 明黄 | `#A16207` | `#B45309` | `#B45309` |
| danger | `#DC2626` | `#FF3860` 玫红 | `#BE123C` 玫 | `#B91C1C` | `#B91C1C` |
| 中性灰 | 偏青的灰 | 中性灰 zinc | 石板灰 slate（冷，带蓝）| 暖灰 stone（带米/棕）| 暖灰 stone |
| 点缀色 | — | — | — | — | **珊瑚 `#EC7E5B`**（非交互）|

侧栏五版统一为浅色 `#FFFFFF`。

**五版的取舍**：

- **青绿**：有品牌辨识度，但主色与 success 同为绿调，
  必须刻意把 success 改成草绿才不糊。
- **原配色**：框架默认值，改造成本最低（`preferences.ts` 里连
  `colorPrimary` 都不用写）。但 success/warning/danger 是框架原值，
  **饱和度和明度都偏高**，密集表格里三种状态同屏时比较跳。
- **靛蓝**：保留蓝色系在后台的稳妥感，但比默认蓝更偏紫、更现代。
  主色是蓝紫，与绿/橙/红色相天然拉得开，**不需要**像青绿版那样
  刻意处理 success；中性色用石板灰与主色同源，整屏更整。
- **暖砂**：唯一跳出冷色系的一版。中性走暖灰、页面底是暖白，
  目标是**久看不累**（一天盯八小时，冷白底最费眼），气质偏「文档/内容」类。
  代价是与主流后台（清一色冷蓝）差异最大；且主色是绿，
  与青绿版一样需要把 success 往橄榄绿推来拉开距离。
- **珊瑚**：外部给定色方案。珊瑚**只做点缀不做交互**，
  可交互元素交给深青——详见下节。

## 珊瑚版：为什么珊瑚不做主色

外部给定三个色值 `#FCDED5` / `#F7B19C` / `#EC7E5B`，同色相 H≈14°，
明度 91% / 79% / 64%——**这是一条只有浅段的色阶**。

`#EC7E5B` 白字仅 **2.73:1**、作白底文字同样 **2.73:1**，两头都够不着 AA，
所以它既不能做按钮底、也不能做链接色。可选的两条路：

| | 做法 | 问题 |
|---|---|---|
| 补深段 | 加 `#C2410C` 作可交互色 | 色相虽同，但那已经是另一个颜色了，给定色反而没露出 |
| **拆职能**（本方案）| 珊瑚专做点缀，交互交给深青 | 给定色原样保留在最显眼的点缀位 |

**最终方案**：可交互色 = 深青 `#0F766E`（白字 5.47:1），
与珊瑚色相差 **161°** 近互补——冷暖对比反而让珊瑚在点缀位置最跳得出来。

珊瑚的四个用武之地（全部是底色或图形，**不承载文字**）：
标签底 · 图表色 · 选中行标记 · 统计卡强调数字。
压在浅珊瑚底上的文字一律用深段 `--accent-text #7C2D12`（7.38:1）。

一个额外好处：珊瑚退居点缀后不再占用橙红区，
warning / danger 可以回到常规取值；若珊瑚作主色，二者会与它撞色
（`#A16207` 差 18°、`#B91C1C` 差 17°），必须刻意推开色相。

中性色配 **暖灰 stone**：与珊瑚色相仅差 11° 属同源；
换成冷灰（slate 159° / zinc 134°）压在珊瑚旁会明显发脏。

规范页见 `coral.html`，含色阶、用法边界（✓/✗ 对照）与落地变量表。

### 对比度校验

五版的关键配对都过了 WCAG AA（正文 4.5:1）。做新配色时容易踩的两个坑：

1. **语义色标签**是小字号，必须按 4.5:1 而非大字号的 3:1 来定。
   靛蓝版初稿 warning 用常见的 `#D97706`，在浅底上只有 **2.91:1**，不合格，
   最终压到 `#A16207`。
2. **主色与 success 若同色系**，光看对比度看不出问题——两者对各自背景
   都合格，但彼此之间会糊。要同时看**色相差**和**明度比**：
   暖砂版 success 从 `#4D7C0F` 调到 `#3F6212`，就是因为前者与主色明度比
   仅 **1.00**（完全同明度）；调整后为 56° / 1.41，优于青绿版基准 33° / 1.14。

## 设计决策记录

几个不是随手定的点：

1. **success 用草绿 `#16A34A` 而非青绿**
   主色已是青绿，若 success 也用青绿，密集表格里「主色按钮」和「启用状态」会糊成一片。刻意拉开色相。

2. **语义色统一降饱和**
   后台一屏几十行，高饱和红黄会不断抢注意力。降饱和后仍可辨识，但不「跳」。

3. **折叠态分组标题退化为分隔线**
   初版用 `···` 占位，实测视觉噪音大且无信息量，改为 1px 分隔线。

4. **折叠态父项继承子项选中态**（`menu__item--has-active`）
   展开时靠子项高亮定位；一旦折叠子项不可见，父项不高亮就完全失去「我在哪」的感知。

5. **操作列按钮常驻，不做 hover 才显示**
   后台需要可发现性，hover 才出现会让不熟悉的用户找不到入口。

6. **表头 `position: sticky`**
   长列表滚动时表头不丢失。

7. **`.app__main` 加 `min-width: 0`**
   flex 子项默认 `min-width: auto`，宽表格会把整个布局撑破导致 body 横向滚动。已验证 `bodyScrollW === winW`。
